# Design System Selection

Select one complete visual system from the 67 Awesome Design skills bundled alongside Tiny Causal Worlds. Each style is an independent installed skill containing `SKILL.md` and `DESIGN.md`; treat the pair as the authoritative specification.

## Selection process

1. Use the available skill catalog descriptions to identify plausible systems without loading every full specification.
2. Internally shortlist candidates by documented brand mission, interaction character, visual hierarchy, palette intention, emotional register, audience fit, platform fit, and accessibility viability.
3. Read the full `SKILL.md` and companion `DESIGN.md` from the strongest candidate skill packages.
4. Select exactly one system. Present only the winner unless the user explicitly asks to compare alternatives.
5. Defend the selection with concrete rules from its documents, not aesthetic adjectives or a moodboard.

Match the design to the causal and instructional character of the world, not to a superficial subject stereotype. Consider whether the system supports observation, comparison, consequence, density, pace, emotional stakes, and the learner's context.

## Fidelity invariant

Apply the selected system faithfully:

- retain its original color palette and tokens exactly;
- retain its typography, spacing, components, borders, surfaces, motion, interaction states, imagery rules, and voice;
- use only combinations and variants authorized by its documentation;
- do not recolor, translate colors by semantic role, blend systems, create a hybrid, or supply a vague moodboard;
- do not borrow an accent, component, or motif from another bundled style.

If the system cannot meet the subject, platform, interaction, or accessibility requirements while preserving its rules, reject it and choose another intact system. Do not repair incompatibility by inventing colors or mutating the design language.

## Required defense

At the World Gate, name the selected system and explain:

- how its documented brand mission supports the learning experience;
- how its layout and component language expose the causal structure;
- how its original palette and visual hierarchy encode state and consequence using documented roles;
- how its interaction and motion rules support prediction, feedback, and replay;
- why it fits the audience, stakes, platform, and accessibility needs.

Reference exact tokens or rules where useful. Keep the defense concise, testable, and implementation-oriented. Do not output color explorations, alternative palettes, inspiration collages, or multiple stylistic directions.

If a selected bundled skill or its companion `DESIGN.md` is missing, report that the installation bundle is incomplete instead of fabricating a system from memory.
