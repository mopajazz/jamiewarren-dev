# Build and Validation

Read this only after the user approves the World Gate.

## Implement the approved world

Build for the platform and delivery constraints established during discovery. Preserve the approved causal claim, learner controls, system rules, feedback, boundaries, and selected design system. Do not add unapproved features merely because the platform makes them convenient.

Prefer a complete thin slice over a broad prototype: the smallest implementation that supports prediction, meaningful action, observable consequence, revision, and replay.

Keep instructional explanation close to the evidence that prompted it. Use concise orientation and prompts, then let the system carry the explanation. Make reset, comparison, progress, and current state understandable without requiring hidden gestures or guesswork.

## Validate the causal engine

Test meaningful invariants and boundary cases rather than only checking that controls respond:

- identical initial conditions and actions produce the expected result unless randomness is intentional;
- directional relationships, thresholds, delays, accumulation, equilibrium, and failure states behave as approved;
- impossible or disallowed states cannot be reached accidentally;
- simplifying assumptions remain visible and do not imply a false transfer claim;
- replay and reset restore an understandable baseline;
- the learner cannot complete the experience while bypassing the primary causal relationship.

## Validate the learning experience

Confirm that a learner can:

- identify the question the world invites them to investigate;
- form a prediction before acting;
- understand what can be manipulated;
- perceive what changed and connect it to an action;
- compare outcomes and revise an explanation;
- apply the causal claim to a new case or authentic task.

## Validate the interface

Verify responsive behavior, keyboard operation, visible focus, contrast using the selected system's original allowed combinations, reduced-motion behavior, text alternatives, readable status changes, and non-color cues. If accessibility requires unauthorized changes to the selected system, stop and return to design-system selection rather than altering the palette.

Test the actual deliverable in its intended environment when available. Provide the completed artifact and only the integration instructions relevant to the selected platform.
